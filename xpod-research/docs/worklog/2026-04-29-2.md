# xPod 集群 GPU 调度环境配置工作日志

**日期**：2026-04-29  
**节点环境**：Kubernetes v1.31.14，8节点集群（1 master + 7 workers）  
**GPU 硬件**：NVIDIA A10（安装于 gpu-node-1）  
**目标**：打通 Volcano 整卡调度 + vGPU 调度全链路

## 问题 1：volcano-gpu-test Pod 一直 Pending

**现象**

```
Warning  FailedScheduling  volcano  1/1 tasks in gang unschedulable: pod group is not ready, 1 Pending, 1 minAvailable; Pending: 1 Unschedulable
```

**排查**

```bash
kubectl get nodes -o custom-columns="NAME:.metadata.name,GPU:.status.allocatable.nvidia\.com/gpu"
# 结果：gpu-node-1 显示 GPU=0，leosuek8s 显示 GPU=1
```

节点 `gpu-node-1` 虽然有 A10 GPU，但 `nvidia.com/gpu` 资源为 0，说明 device-plugin 未能上报资源。

**根因**：`gpu-node-1` 上 nvidia-container-toolkit 未配置 containerd runtime。

---

## 修复 1：配置 containerd 使用 nvidia runtime

在 `gpu-node-1` 上执行：

```bash
sudo nvidia-ctk runtime configure --runtime=containerd
sudo systemctl restart containerd
```

**验证**：配置写入 `/etc/containerd/conf.d/99-nvidia.toml`，主配置通过 `imports = ["/etc/containerd/conf.d/*.toml"]` 自动加载。

## 问题 2：device-plugin 仍报 `Incompatible strategy detected auto`

**现象**

```
E  factory.go:113  Incompatible strategy detected auto
E  factory.go:114  If this is a GPU node, did you configure the NVIDIA Container Toolkit?
I  main.go:397     No devices found. Waiting indefinitely.
```

**根因**：`deviceDiscoveryStrategy: auto` 要求 containerd default runtime 为 nvidia，但当前 default runtime 是 runc。

**修复**：patch daemonset 强制使用 nvml 策略：

```bash
kubectl patch daemonset nvidia-device-plugin -n kube-system --type=json -p='[
  {
    "op": "add",
    "path": "/spec/template/spec/containers/0/env",
    "value": [{"name": "DEVICE_DISCOVERY_STRATEGY", "value": "nvml"}]
  }
]'
```

## 问题 3：nvml 策略报 `ERROR_LIBRARY_NOT_FOUND`

**现象**

```
E  factory.go:94  Failed to initialize NVML: ERROR_LIBRARY_NOT_FOUND.
```

**根因**：device-plugin 容器内找不到 `libnvidia-ml.so`，容器挂载的 `/driver-root` 路径不存在。

**确认**：宿主机驱动库位于 `/usr/lib/x86_64-linux-gnu/libnvidia-ml.so`，标准路径。

**修复**：给 daemonset 挂载宿主机根目录：

```bash
kubectl patch daemonset nvidia-device-plugin -n kube-system --type=json -p='[
  {
    "op": "replace",
    "path": "/spec/template/spec/containers/0/env",
    "value": [
      {"name": "DEVICE_DISCOVERY_STRATEGY", "value": "nvml"},
      {"name": "NVIDIA_DRIVER_ROOT", "value": "/driver-root"}
    ]
  },
  {
    "op": "add",
    "path": "/spec/template/spec/volumes/-",
    "value": {"name": "driver-root", "hostPath": {"path": "/", "type": ""}}
  },
  {
    "op": "add",
    "path": "/spec/template/spec/containers/0/volumeMounts/-",
    "value": {"name": "driver-root", "mountPath": "/driver-root", "readOnly": true}
  }
]'
```

**验证**：

```bash
kubectl get nodes -o custom-columns="NAME:.metadata.name,GPU:.status.allocatable.nvidia\.com/gpu"
# gpu-node-1  1  ✅
# leosuek8s   1  ✅
```

## 问题 4：Volcano 调度器仍报 `Insufficient nvidia.com/gpu`

**现象**：device-plugin 修复后，Volcano Job 提交仍然调度失败，所有节点报资源不足。

**排查**：Volcano queue 未配置 GPU capacity。

```bash
kubectl get queue default -o yaml
# spec.capability 只有 pods: "100"，无 nvidia.com/gpu
```

**修复**：

```bash
kubectl patch queue default --type=json -p='[
  {
    "op": "add",
    "path": "/spec/capability",
    "value": {
      "cpu": "32",
      "memory": "64Gi",
      "nvidia.com/gpu": "2"
    }
  }
]'
```

## 问题 5：Volcano Job 提交后 podgroup 不存在，Pod 不生成

**现象**：`kubectl get podgroup -n default` 无结果，vcjob STATUS 一直 Pending。

**排查**：Volcano controller 日志显示：

```
PodGroup default:volcano-gpu-smoke unschedule, reason: 1/0 tasks in gang unschedulable: pod group is not ready, 1 minAvailable
```

`1/0` 表示 minAvailable=1 但 queue 有效容量为 0，queue capacity 未生效（旧版本 bug）。

**解决**：重新提交新 Job（`vcjob-gpu-2`），queue patch 生效后调度成功。

## 验证 1：整卡调度（nvidia.com/gpu）✅

```bash
cat <<EOF | kubectl apply -f -

  name: vcjob-gpu-2
  namespace: default

  minAvailable: 1
  schedulerName: volcano
  queue: default
```

## 问题 6：vGPU 调度报 `UnexpectedAdmissionError`

**现象**：

```
Allocate failed due to rpc error: code = Unknown desc = pods "vcjob-vgpu-1-vgpu-task-0" is forbidden:
User "system:serviceaccount:volcano-system:volcano-device-plugin" cannot patch resource "pods"
```

**根因**：`volcano-device-plugin` ServiceAccount 缺少 patch pods 的 RBAC 权限。

**修复**：

```bash
kubectl create clusterrole volcano-device-plugin-patch \
  --verb=patch,get,list \
  --resource=pods

kubectl create clusterrolebinding volcano-device-plugin-patch \
  --clusterrole=volcano-device-plugin-patch \
  --serviceaccount=volcano-system:volcano-device-plugin
```

同时在 `volcano-scheduler-configmap` 中启用 deviceshare 插件：

```yaml
- plugins:
  - name: deviceshare
    arguments:
      deviceshare.VGPUEnable: true
```
