# HAMi 安装工作日志

**日期：** 2026-04-22  
**目标：** 在 xPod K8s 集群中安装 HAMi，实现 A10 GPU 虚拟化切分  
**节点：** gpu-node-1 (192.168.1.121)，A10 24G 通过 PCIe Passthrough 直通

---

## 一、背景

xPod 集群已有一张 NVIDIA A10 显卡通过 PCIe Passthrough 直通给 gpu-node-1 VM，需要用 HAMi 将其虚拟化为多个 vGPU，实现多任务并发使用同一张物理卡。

---

## 二、安装过程

### 2.1 添加 HAMi Helm 仓库

```bash
helm repo add hami-charts https://project-hami.github.io/HAMi/
helm repo update
```

### 2.2 首次安装（缺少 device plugin）

```bash
helm install hami hami-charts/hami \
  --namespace hami-system \
  --create-namespace \
  --set devicePlugin.nodeSelector."xpod\.io/node-type"=gpu
```

**问题：** 只部署了 scheduler，没有 DaemonSet（device plugin）。

```bash
kubectl get all -n hami-system
# 只有 hami-scheduler deployment，没有 DaemonSet
```

### 2.3 升级安装加入 device plugin

```bash
helm upgrade hami hami-charts/hami \
  --namespace hami-system \
  --set devicePlugin.nodeSelector."xpod\.io/node-type"=gpu
```

**问题：** device plugin pod 报 `ImagePullBackOff`，无法从 docker.io 拉取 `projecthami/hami:v2.8.1`。

---

## 三、踩坑记录

### 坑1：device plugin 镜像拉取失败

**现象：** `hami-device-plugin` pod 一直 ImagePullBackOff。

**原因：** containerd 服务即使配置了代理也无法拉取 docker.io 镜像，速度极慢或超时。

**解决：** 在 gpu-node-1 上用 crictl 手动拉取（crictl 可以直接读取系统代理环境变量）：

```bash
# 在 gpu-node-1 上
sudo HTTPS_PROXY=http://192.168.1.72:7897 crictl pull docker.io/projecthami/hami:v2.8.1
```

然后将 DaemonSet 的 imagePullPolicy 改为 Never，避免重复从外网拉取：

```bash
kubectl patch daemonset hami-device-plugin -n hami-system \
  --type='json' \
  -p='[
    {"op":"replace","path":"/spec/template/spec/containers/0/imagePullPolicy","value":"Never"},
    {"op":"replace","path":"/spec/template/spec/containers/1/imagePullPolicy","value":"Never"}
  ]'
```

---

### 坑2：nodeSelector 配置错误，device plugin 调度到错误节点

**现象：** 有两个 `hami-device-plugin` pod，分别在 gpu-node-1 和 leosuek8s 上。

**原因：** leosuek8s 宿主机之前被打上了 `gpu=on` 标签（HAMi DaemonSet 的 nodeSelector 是 `gpu=on`，不是 `xpod.io/node-type=gpu`）。

**解决：**

```bash
# 给 gpu-node-1 加上正确的标签
kubectl label node gpu-node-1 gpu=on

# 去掉宿主机的错误标签
kubectl label node leosuek8s gpu-
```

---

### 坑3：device plugin CrashLoopBackOff - invalid device discovery strategy

**现象：** device plugin 启动后报错：
```
error starting plugins: error getting plugins: unable to create plugins: 
failed to construct resource managers: invalid device discovery strategy
```

**原因：** containerd 的 `defaultRuntimeName` 是 `runc` 而不是 `nvidia`，device plugin 无法通过 nvidia runtime 发现 GPU 设备。

**诊断：**
```bash
sudo crictl info | grep defaultRuntimeName
# "defaultRuntimeName": "runc"  ← 错误，应该是 nvidia
```

**解决：** 在 gpu-node-1 上重新配置 nvidia-container-toolkit，并设置为默认 runtime：

```bash
# 先安装 nvidia-container-toolkit（需要代理，速度较慢）
sudo tee /etc/apt/apt.conf.d/proxy.conf <<EOF
Acquire::http::Proxy "http://192.168.1.72:7897";
Acquire::https::Proxy "http://192.168.1.72:7897";
EOF

curl -fsSL --proxy http://192.168.1.72:7897 \
  https://nvidia.github.io/libnvidia-container/gpgkey | \
  sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg

curl -s -L --proxy http://192.168.1.72:7897 \
  https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | \
  sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | \
  sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list

sudo apt-get update
sudo apt-get install -y nvidia-container-toolkit

# 配置 containerd 使用 nvidia runtime 并设为默认
sudo nvidia-ctk runtime configure --runtime=containerd --set-as-default
sudo systemctl restart containerd

# 验证
sudo crictl info | grep defaultRuntimeName
# "defaultRuntimeName": "nvidia"  ← 正确
```

## 五、使用说明

### 提交 GPU 任务

请求 vGPU 时指定显存大小：

```yaml
resources:
  limits:
    nvidia.com/gpu: "1"       # 请求 1 个 vGPU
    nvidia.com/gpumem: "8192" # 限制 8G 显存
```

A10 共 24G 显存，同时可运行 3 个 8G 的任务。

### 当前集群 GPU 资源

| 节点 | GPU | 显存 | HAMi vGPU 数 |
|------|-----|------|-------------|
| gpu-node-1 | NVIDIA A10 | 24G | 10 |

## 六、关键命令速查

```bash
# 查看 HAMi 组件状态
kubectl get pods -n hami-system

# 查看 GPU 节点资源
kubectl get node gpu-node-1 -o json | grep "nvidia.com"

# 查看 HAMi device plugin 日志
kubectl logs -n hami-system <hami-device-plugin-pod> -c device-plugin

# 重启 device plugin
kubectl delete pod -n hami-system <hami-device-plugin-pod>
```
