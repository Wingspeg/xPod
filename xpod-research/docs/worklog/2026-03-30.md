## 今日记录（按“每次我做了啥”）

### 1) 完成多组件部署与 8 台 VM 集群形态落地
**目的**
- 在同一实验集群中具备三类能力：
  - Volcano：面向批处理/AI 作业的算力调度能力
  - Fluid：面向数据集的分布式数据加速与数据调度能力
  - Koordinator：面向 QoS、绑核、NUMA 等生产级资源管理能力

**做了什么**
- 虚拟机集群形态落地（细节待补充）：
  - 使用 KVM 在 leosuek8s 上创建 8 台 VM，每台规格 4 核 8G 40G，对应节点：gpu-node-1/2/3、cpu-node-1/2、data-node-1/2、algo-node-1。
  - 为 VM 分配固定 IP：192.168.100.11–.13（GPU 节点）、.21–.22（CPU 节点）、.31–.32（数据节点）、.41（算法节点），统一挂载到 192.168.100.0/24 内网。
  - 配置集群访问与运维基础：配置 SSH 免密、NTP 时间同步、常用运维工具与 sudo 权限，保证后续实验过程中的远程操作可控。
  - 通过 /opt/k8s-workspace/scripts/vm/join-k8s.sh 将 8 台 VM 作为 worker node 加入现有 k8s 集群，并为每个节点打上 node-role.kubernetes.io/{gpu-compute,cpu-compute,data,algorithm} 等标签。
  - 验收：kubectl get nodes 显示 1 个 control-plane + 8 个 Ready 的工作节点，系统核心组件稳定运行。
- 部署 Volcano：
  - 使用 manifests/volcano/installer/volcano-development.yaml 与根目录 volcano-crds.yaml 在 volcano-system 命名空间安装 CRD、scheduler 与 controller。
  - 验证 CRD 与核心组件状态：通过 kubectl get pods -n volcano-system 与 kubectl get crd | grep volcano 检查 scheduler/controller 与 CRD 是否处于 Running/Established 状态。
  - 提交 test-volcano-job.yaml 作为最小 VCJob 示例，验证作业可以被 Volcano 调度到 gpu-node/cpu-node 资源池。
- 部署 Fluid：
  - 使用官方 Helm chart 或 manifests 在 fluid-system 命名空间安装 Dataset/Runtime 等 CRD 与 controller。
  - 验证 CRD 与组件运行状态：kubectl get pods -n fluid-system 与 kubectl get crd | grep fluid，确认 Dataset/Runtime 等 CRD 已注册且 controller 处于 Running。
  - 验证最小数据集加速链路：创建 Dataset + Runtime 挂载本地/远端数据目录，在 data-node-* 上预热缓存，应用 Pod 通过挂载点访问数据，确认命中 Fluid 缓存。
- 部署 Koordinator：
  - 在 koordinator-system 命名空间安装 Koordinator controller 与 koord-scheduler，开启 QoS/绑核/NUMA 感知等基础特性。
  - 验证 Koordinator 相关 CRD 与组件运行状态：kubectl get pods -n koordinator-system 与 kubectl get crd | grep koordinator，确认控制面正常。
  - 验证基础能力可用：在 algo-node-1 与部分 CPU 节点上配置 QoS class 与调度策略，提交示例 Pod，观察调度结果与绑核/NUMA 行为是否符合预期。
- 做实验可控性准备（为后续对比实验减少变量）：
  - 设计并应用节点标签与约束：使用 node-role.kubernetes.io/*、topology.kubernetes.io/zone 等标签区分 data/compute/algorithm 节点，并通过 nodeSelector/taint 约束不同类型工作负载。
  - 规划命名空间、资源配额、优先级/抢占策略边界：为 baseline/xpod/benchmark 等实验创建独立 namespace，配置 ResourceQuota 与 LimitRange，避免实验间相互抢占资源。

**结果/产出**
- 三组件部署完成，实验集群具备后续实现“统一调度编排单元（xPod）→ 多调度器路由/联动”的基础能力。
- 集群规模固定为 8 台 VM，为后续实验的可控性与可比性提供约束条件。
