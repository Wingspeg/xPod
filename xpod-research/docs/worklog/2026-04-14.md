## 一、初始排查：确认HAMI及GPU相关环境异常

**操作时间**：2026年4月14日

**操作步骤**：

1. **查看HAMI相关Pod状态**执行命令：`kubectl get pods \-A \| grep \-i hami`命令输出：HAMI调度器Pod正常Running（未报错，说明HAMI本身部署无问题，问题出在GPU环境配置）

2. **查看NVIDIA device\-plugin状态**执行命令：`kubectl get pods \-n kube\-system \| grep nvidia`命令输出：nvidia\-device\-plugin相关Pod部分Pending、部分异常（初步判断GPU识别失败）

3. **查看nvidia\-device\-plugin日志，排查GPU识别失败原因**执行命令：`kubectl logs \-n kube\-system $\(kubectl get pods \-n kube\-system \| grep nvidia \| awk \&\#39;\{print $1\}\&\#39;\)`命令输出（报错关键信息）：`Incorrect Usage: flag provided but not defined: \-devices
E0414 08:19:54\.062624       1 main\.go:188\] flag provided but not defined: \-devices`排查结论：之前部署nvidia\-device\-plugin时使用了\-\-devices参数，该参数在当前插件版本（v0\.19\.0）中不支持，导致插件启动失败，无法识别GPU。

4. **确认物理机GPU识别情况**执行命令：`nvidia\-smi \-L`命令输出：`GPU 0: NVIDIA A10 \(UUID: GPU\-ea6b93fe\-4a35\-dc9f\-9858\-4949770e1b55\)`结论：物理机驱动正常，可正常识别A10 GPU，GT710亮机卡未被识别（不影响GPU使用，仅作为亮机用途）。

**操作备注**：HAMI本身无异常，核心问题是nvidia\-device\-plugin配置错误，导致GPU无法被K8s识别，进而HAMI无法调度GPU资源。

## 二、修复nvidia\-device\-plugin配置：替换错误参数

**操作时间**：2026年4月14日

**操作步骤**：

1. **删除原有异常的nvidia\-device\-plugin DaemonSet**执行命令：`kubectl delete daemonset nvidia\-device\-plugin \-n kube\-system`命令输出：daemonset\.apps \&\#34;nvidia\-device\-plugin\&\#34; deleted（确认旧插件已删除）

2. **重新部署nvidia\-device\-plugin，使用正确参数（替换\-\-devices为环境变量指定UUID）**执行命令：`kubectl apply \-f \- \&lt;\&lt;EOF
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: nvidia\-device\-plugin
  namespace: kube\-system
spec:
  selector:
    matchLabels:
      name: nvidia\-device\-plugin
  template:
    metadata:
      labels:
        name: nvidia\-device\-plugin
    spec:
      tolerations:
      \- operator: Exists
      nodeSelector:
        kubernetes\.io/hostname: leosuek8s
      containers:
      \- name: nvidia\-device\-plugin
        image: nvcr\.io/nvidia/k8s\-device\-plugin:v0\.19\.0
        env:
        \- name: NVIDIA\_VISIBLE\_DEVICES
          value: \&\#34;GPU\-ea6b93fe\-4a35\-dc9f\-9858\-4949770e1b55\&\#34;
        args:
        \- \&\#34;\-\-fail\-on\-init\-error=false\&\#34;
        \- \&\#34;\-\-device\-discovery\-strategy=nvml\&\#34;
        securityContext:
          privileged: true
        volumeMounts:
        \- name: device\-plugin
          mountPath: /var/lib/kubelet/device\-plugins
      volumes:
      \- name: device\-plugin
        hostPath:
          path: /var/lib/kubelet/device\-plugins
EOF`命令输出：daemonset\.apps/nvidia\-device\-plugin created（确认新插件部署成功）

3. **查看重新部署后的插件日志**执行命令：`kubectl logs \-n kube\-system $\(kubectl get pods \-n kube\-system \| grep nvidia \| awk \&\#39;\{print $1\}\&\#39;\)`命令输出（报错关键信息）：`E0414 08:20:48\.038905       1 factory\.go:94\] Failed to initialize NVML: ERROR\_LIBRARY\_NOT\_FOUND\.
E0414 08:20:48\.038928       1 factory\.go:95\] If this is a GPU node, did you set the docker default runtime to \`nvidia\`?`排查结论：插件仍无法识别GPU，报错提示未设置docker默认运行时为nvidia，进一步排查containerd运行时配置。

**操作备注**：已修复插件参数错误，但新的报错显示容器运行时配置异常，这是GPU无法识别的核心原因。

## 三、修复containerd运行时配置：切换默认运行时为nvidia

**操作时间**：2026年4月14日

**操作步骤**：

1. **检查nvidia\-container\-runtime是否安装**执行命令：`which nvidia\-container\-runtime`命令输出：/usr/bin/nvidia\-container\-runtime（确认nvidia\-container\-runtime已安装）

2. **检查nvidia\-container\-toolkit是否安装**执行命令：`sudo apt install \-y nvidia\-container\-toolkit`命令输出：nvidia\-container\-toolkit is already the newest version \(1\.19\.0\-1\)（确认工具包已安装，无需更新）

3. **查看containerd默认运行时配置**执行命令：`cat /etc/containerd/config\.toml \| grep \-A5 \-B5 default\_runtime\_name`命令输出（关键信息）：`      default\_runtime\_name = \&\#34;runc\&\#34;`结论：containerd默认运行时为runc，未切换为nvidia，导致容器无法访问NVIDIA驱动和GPU资源，这是核心问题。

4. **使用官方工具配置containerd运行时**执行命令：`sudo nvidia\-ctk runtime configure \-\-runtime=containerd \-\-set\-as\-default
sudo systemctl restart containerd`命令输出：`INFO\[0000\] Using config version 3                       
INFO\[0000\] Using CRI runtime plugin name \&\#34;io\.containerd\.cri\.v1\.runtime\&\#34; 
INFO\[0000\] Wrote updated config to /etc/containerd/conf\.d/99\-nvidia\.toml 
INFO\[0000\] It is recommended that containerd daemon be restarted\.`

5. **验证containerd默认运行时是否切换成功**执行命令：`cat /etc/containerd/config\.toml \| grep default\_runtime\_name`命令输出：default\_runtime\_name = \&\#34;runc\&\#34;（配置未生效，官方工具未覆盖主配置文件）

6. **手动强制修改containerd配置，切换默认运行时为nvidia**执行命令：`sudo sed \-i \&\#39;s/default\_runtime\_name = \&\#34;runc\&\#34;/default\_runtime\_name = \&\#34;nvidia\&\#34;/g\&\#39; /etc/containerd/config\.toml`命令输出：无（无报错即表示修改成功）

7. **重启containerd，使配置生效**执行命令：`sudo systemctl restart containerd`命令输出：无（无报错即表示重启成功）

8. **再次验证默认运行时**执行命令：`cat /etc/containerd/config\.toml \| grep default\_runtime\_name`命令输出：default\_runtime\_name = \&\#34;nvidia\&\#34;（确认配置已生效，containerd默认运行时已切换为nvidia）

**操作备注**：containerd运行时配置是本次GPU识别失败的核心原因，手动修改配置后已成功切换默认运行时为nvidia，为后续GPU识别奠定基础。
