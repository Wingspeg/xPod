### 1) 完成 DAG 代价模型与评分相关实现（代码由助手协作完成）
**目的**
- 把“统一调度”的关键因素显式化：计算耗时、数据传输时间、网络延迟、SLA 违约惩罚等，形成可复现实验的评分基础。

**做了什么**
- 明确“统一表征”的最小数据闭环：输入 workload 一行记录 → 映射为（算法/数据/算力）结构 → 计算代价与评分 → 供调度器选择节点。
- 梳理并固化关键字段（按“可被 trace/CSV 提供”为约束）：
  - 计算侧：compute_type、duration_s
  - 数据侧：dataset_id、dataset_size_bytes、data_node
  - 算法/作业侧：framework、algo_type、image、qos_class、priority、sla_ms
- 实现/完善 DAG 与评分相关代码模块化结构：
  - 定义 DAG 相关数据结构（AlgorithmNode/DataNode/ComputeNode/XPodDAG 等）
  - 实现传输时间估计函数 estimate_transfer_ms（带宽 + 基础延迟 → 传输耗时）
  - 实现评分函数 score_request（计算时长 + 传输代价 + 网络延迟 + SLA 惩罚项）
  - 处理异常/边界输入（缺失字段、空字符串、负值/零值带宽等的兜底策略）
- 打通与调度器侧的接口预期（面向后续 schedule_one 使用）：
  - 将评分权重参数（alpha/beta/gamma/sla_penalty）作为可配置项，由 CLI 透传
  - 保持输入/输出为轻量数据结构，便于后续清单生成与回放脚本复用

**结果/产出**
- DAG 模型与评分函数可用于后续的 schedule_one 决策输入，支撑“baseline vs 本方案”在同一指标定义下做对比。

- 可引用结论（一句话）：将网络与数据代价内化到服务调用图的边/节点属性，可把统一调度问题转化为可计算的代价最小化/评分最优化问题。

### 2) 清洗 Alibaba Cluster Trace GPU v2020，并补齐四场景实验所需字段（含模拟数据输入）
**目的**
- 将原始 trace 统一转换为可直接喂给调度器与回放系统的“请求级 workload CSV”，并补齐统一调度实验必需但 trace 中不完备的字段（数据集、网络、冷启动、QoS/SLA 等）。

**做了什么**
- 基于原始表（raw/ 下 pai_instance_table、pai_task_table、pai_job_table 等）抽取并关联实例与任务资源信息，生成请求级记录：
  - 以 instance 表的 start/end 时间计算 duration，并过滤异常/过长样本（max_duration_s）。
  - 根据任务资源中是否请求 GPU 将 compute_type 划分为 GPU/CPU，并生成拓扑/组调度相关字段（如 gang_size、topology_req）。
- 为统一调度补齐“数据服务”侧字段与网络侧字段：
  - 生成 datasets.csv（预置数据集目录：dataset_id/size_bytes/object_count/hot_fraction，并按 seed 绑定到 data_node）。
  - 为每条请求分配 dataset_id 与 dataset_size_bytes，并根据数据/算力节点生成 network_latency_ms、network_bandwidth_mbps 与 estimated_transfer_ms。
  - 使用 (compute_node, dataset_id) 作为缓存键，推导 cold_start 与 bytes_to_load（冷启动加载全量数据，命中缓存加载为 0）。
- 为算法服务/作业侧补齐必要字段（用于 DAG 与调度评分）：
  - 根据 framework 与 compute_type 推导 algorithm_type，并生成 algorithm_image、batch_size、learning_rate、qos_class、priority、sla_ms。
- 生成四个实验场景对应的清洗输出，并写入字段映射说明（field_mapping.json），便于论文描述“从原始表到请求字段”的可追溯性。
- 为保证 CPU 场景/混合场景样本量与分布可控，按 cpu_synth_rate 从 GPU trace 触发合成 CPU 请求，补齐到 min_cpu_rows 目标（source=synthetic），并同样补齐 submit_time/start/end/duration 与数据/网络字段。

**结果/产出**
- 四场景清洗输出默认落盘到：
  - scene1（算法侧/CPU 请求）：datasets/alibaba-cluster-trace-gpu-v2020/processed/scene1-algo/cpu_requests.csv
  - scene3（算力侧/GPU 请求）：datasets/alibaba-cluster-trace-gpu-v2020/processed/scene3-compute/gpu_requests.csv
  - scene2（数据侧/数据请求与元信息）：datasets/alibaba-cluster-trace-gpu-v2020/processed/scene2-data/{data_requests.csv,datasets.csv,machine_metrics.csv,sensor_events.csv}
  - scene4（联合场景/统一请求表）：datasets/alibaba-cluster-trace-gpu-v2020/processed/scene4-joint/xpod_requests.csv
  - 字段映射：datasets/alibaba-cluster-trace-gpu-v2020/processed/_meta/field_mapping.json

**对论文的贡献**
- 对应章节：数据集与预处理（Dataset / Preprocessing）；实验设置（Workload Construction）
- 计划图表/表格：字段对照表（trace→workload 字段）；四场景数据统计表（请求数、GPU/CPU 占比、时长分布）
- 可引用结论（一句话）：通过字段补齐与合成策略，可将原始集群 trace 转换为支持“算法/算力/数据”三要素统一评测的请求级 workload。

**可复现信息（可选，写关键项即可）**
- 入口脚本/模块：experiments/datagen/parse_alibaba_gpu_v2020.py
- 关键参数：--seed、--data-nodes/--gpu-nodes/--cpu-nodes、--max-duration-s、--min-cpu-rows、--cpu-synth-rate
- 产物路径：datasets/alibaba-cluster-trace-gpu-v2020/processed/
