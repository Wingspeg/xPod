# 工作日志 — Volcano vGPU 调试全程记录

**日期**: 2026-05-07  
**环境**: xPod 实验集群，k8s v1.31.14，gpu-node-1（NVIDIA A10，23028MB），Volcano v1.9.0 → v1.10.0

---

## 背景

xPod 调度研究项目需要验证 Volcano vGPU 功能，通过提交 VolcanoJob 申请 `volcano.sh/vgpu-number` 和 `volcano.sh/vgpu-memory` 资源，确认整条链路可用。

---

## 问题一：Pod 卡在 Pending，volcano 报 Unschedulable

### 现象

```
kubectl get vcjob vgpu-real-test
# STATUS: Pending

kubectl describe pod vgpu-real-test-gpu-task-0
# Events: volcano: 1/1 tasks in gang unschedulable: pod group is not ready, Pending: 1 Unschedulable
```

### 排查过程

检查节点资源注册情况：

```bash
kubectl get nodes -o custom-columns="NAME:.metadata.name,vGPU-NUM:.status.allocatable.volcano\.sh/vgpu-number,vGPU-MEM:.status.allocatable.volcano\.sh/vgpu-memory"
```

发现 `gpu-node-1` 上 `vgpu-number=0`，其余节点均为 `<none>`。

进一步检查 `kube-system` 中 vgpu 相关 Pod：

```bash
kubectl get pods -n kube-system | grep -E "nvidia|gpu"
```

发现只有官方 `nvidia-device-plugin`（注册 `nvidia.com/gpu`），没有任何 HAMi 或 volcano-vgpu 相关 Pod。

检查 `volcano-system`：

```bash
kubectl get pods -n volcano-system | grep vgpu
# volcano-vgpu-device-plugin-plvds   0/1   CrashLoopBackOff
```

### 根本原因

`volcano-vgpu-device-plugin` 一直处于 CrashLoopBackOff，导致节点 vGPU 资源未能正确注册。

## 问题二：volcano-vgpu-device-plugin CrashLoopBackOff — NVML 库找不到

### 现象

```
kubectl logs -n volcano-system volcano-vgpu-device-plugin-plvds
# Failed to initialize NVML: could not load NVML library.
```

### 排查过程

登录 gpu-node-1 确认驱动是否存在：

```bash
ssh leo@192.168.1.121 "find /usr -name 'libnvidia-ml.so*'"
# /usr/lib/x86_64-linux-gnu/libnvidia-ml.so.535.288.01
# /usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1
# /usr/lib/x86_64-linux-gnu/libnvidia-ml.so
```

驱动存在，但查看 DaemonSet 挂载配置：

```bash
kubectl get daemonset -n volcano-system volcano-vgpu-device-plugin -o yaml | grep -A 5 "volumes:"
# hostPath: /usr/local/nvidia
```

### 根本原因

DaemonSet 把宿主机 `/usr/local/nvidia` 挂载进容器，但实际驱动库在 `/usr/lib/x86_64-linux-gnu/`，路径不匹配，容器内找不到 NVML。

### 解决方案

```bash
kubectl edit daemonset -n volcano-system volcano-vgpu-device-plugin
# 将 volumes[].hostPath.path 从 /usr/local/nvidia 改为 /usr/lib/x86_64-linux-gnu
```

修改后 device-plugin 启动成功，日志输出：

```
Registered device plugin for 'volcano.sh/vgpu-number' with Kubelet
Reporting devices GPU-ea6b93fe-...,2,23028,NVIDIA-NVIDIA A10,false:
```

节点资源更新为 `vgpu-number=2`。

## 问题三：UnexpectedAdmissionError — EOF，device-plugin 周期性崩溃

### 现象

```
kubectl describe pod vgpu-real-test-gpu-task-0
# Allocate failed due to rpc error: code = Unavailable desc = error reading from server: EOF
```

### 排查过程

查看 kubelet 日志：

```bash
ssh leo@192.168.1.121 "sudo journalctl -u kubelet --since '5 minutes ago' | grep -i 'vgpu\|EOF'"
# ListAndWatch ended unexpectedly for device plugin err="...EOF"
```

device-plugin 每隔 60-90 秒崩溃一次，kubelet 在 Allocate 时恰好遇到连接断开。

查看 crash 日志：

```bash
kubectl logs -n volcano-system volcano-vgpu-device-plugin-59nh5 --previous
# panic: runtime error: invalid memory address or nil pointer dereference
# plugin.go:313
```

### 根本原因

`projecthami/volcano-vgpu-device-plugin:v1.9.0` 在处理 Allocate 请求时存在 nil pointer bug，触发 panic 导致进程崩溃。

### 解决方案

升级 device-plugin 到 v1.9.1：

```bash
kubectl set image daemonset/volcano-vgpu-device-plugin -n volcano-system \
  volcano-vgpu-device-plugin=projecthami/volcano-vgpu-device-plugin:v1.9.1
```

升级后 device-plugin 稳定运行，不再崩溃。

## 问题四：UnexpectedAdmissionError — no pending pod found on node

### 现象

```
Allocate failed due to rpc error: code = Unknown desc = no pending pod found on node, which is unexpected
```

### 排查过程

**尝试一**：怀疑是 webhook 问题，检查 mutating webhook：

```bash
kubectl get mutatingwebhookconfigurations | grep -i vgpu
# 无结果
```

发现 `hami-webhook` 残留（HAMi 之前卸载不干净），指向已不存在的 `hami-scheduler` service，可能干扰 Pod 创建。删除残留：

```bash
kubectl delete mutatingwebhookconfiguration hami-webhook
```

**尝试二**：检查 volcano-admission 的 webhook 是否包含 vgpu 注入逻辑。查看 Pod admission 日志，发现 Pod 被 webhook 处理后 annotations 里没有任何 vgpu 相关字段。

**尝试三**：查看 volcano-scheduler-configmap，发现 `deviceshare` 插件完全未配置：

```bash
kubectl get cm -n volcano-system volcano-scheduler-configmap -o yaml
# 只有 priority, gang, conformance, overcommit, drf, predicates 等插件
# 没有 deviceshare
```

### 根本原因

volcano-scheduler 的 `deviceshare` 插件未启用，该插件负责在调度时向节点 annotation 写入 Pod 的 vGPU 分配记录。device-plugin 在 Allocate 时查找该记录，找不到就报错。

### 解决方案

编辑 configmap，加入 `deviceshare` 插件：

```bash
kubectl edit cm -n volcano-system volcano-scheduler-configmap
```

```yaml
- name: deviceshare
  arguments:
    deviceshare.VGPUEnable: true
    deviceshare.SchedulePolicy: binpack
```

重启 scheduler：

```bash
kubectl rollout restart deployment -n volcano-system volcano-scheduler
```

## 问题五：deviceshare 插件配置后仍未生效 — volcano v1.9.0 不支持

### 现象

重启 scheduler 后查看日志：

```
Successfully loaded Scheduler conf, actions: [enqueue allocate backfill], plugins: [priority gang conformance]
```

`deviceshare` 没有出现在加载的插件列表中，scheduler 仍把 `volcano.sh/vgpu-number` 当普通扩展资源处理（分配日志中显示 `vgpu-number 1000.00`，异常）。

### 排查过程

确认当前 volcano 版本：

```bash
kubectl describe pod -n volcano-system volcano-scheduler-xxx | grep Image
# docker.m.daocloud.io/volcanosh/vc-scheduler:v1.9.0
```

查阅官方文档：**Volcano vGPU 功能仅在 Volcano > v1.9 可用**，v1.9.0 本身不支持。

### 解决方案

升级 volcano 三个核心组件到 v1.10.0（就地替换镜像，不重建 CRD）：

```bash
kubectl set image deployment/volcano-scheduler -n volcano-system \
  volcano-scheduler=volcanosh/vc-scheduler:v1.10.0
kubectl set image deployment/volcano-controllers -n volcano-system \
  volcano-controllers=volcanosh/vc-controller-manager:v1.10.0
kubectl set image deployment/volcano-admission -n volcano-system \
  admission=volcanosh/vc-webhook-manager:v1.10.0
```

## 问题六：升级后 deviceshare 仍未加载 — configmap YAML 缩进错误

### 现象

升级到 v1.10.0 后，scheduler 加载日志依然是：

```
plugins: [priority gang conformance]
```

### 排查过程

检查 configmap 实际存储内容：

```bash
kubectl get cm -n volcano-system volcano-scheduler-configmap -o jsonpath='{.data}' | python3 -m json.tool
```

发现第二个 `plugins` 块的子项缺少缩进：

```yaml
# 错误（实际存储）
- plugins:
- name: overcommit   # 缺少两个空格缩进
- name: deviceshare

# 正确
- plugins:
  - name: overcommit
  - name: deviceshare
```

### 解决方案

重新编辑 configmap 修复 YAML 缩进，重启 scheduler 后加载日志变为：

```
plugins: [priority gang conformance overcommit drf deviceshare predicates proportion nodeorder binpack]
```
